De la extracción SQL a la prueba de hipótesis

Guía de trabajo con pandas, NumPy y SciPy. Un caso de auditoría de expedición recorre el flujo completo con datos simulados y una conexión adaptable a SQL Server.

Checklist para arrancar una investigación

  1. Delimitar la decisiónPregunta operativa, población, periodo y unidad de análisis.
  2. Extraer de SQLConsulta parametrizada y fuente identificada.
  3. Limpiar y conciliarLlaves, tipos, nulos, denominadores y conteos contra origen.
  4. ExplorarTasas, distribuciones, cobertura y posibles sesgos.
  5. Formalizar H₀ y H₁Métrica, diseño, α y diferencia relevante.
  6. Elegir la pruebaTipo de variable, independencia, grupos y supuestos.
  7. Estimar y contrastarTamaño del efecto, intervalo y valor p.
  8. Comunicar y guardarDecisión, alcance y pasos para reproducir el resultado.
Pregunta del caso. ¿La proporción de envíos auditados con error de expedición difiere entre Gómez y León? La respuesta ayudará a decidir si conviene revisar en detalle el proceso con mayor tasa.

Si estás preparando un análisis confirmatorio, fija la métrica, la hipótesis y el plan antes de ver el resultado por grupo. Si la hipótesis nace de los patrones del análisis preliminar, identifícala como exploratoria y compruébala con un corte independiente fijado de antemano.

Extracción desde SQL Server

Unidad: un envío auditado. Llave: CEDIS + identificador de envío. Denominador: envíos auditados con resultado confirmado en el periodo. Un envío con varios errores cuenta una vez. El ejemplo usa fecha de revisión. Si quieres medir la operación por fecha de expedición, cambia la fecha del corte y verifica si hay auditorías pendientes al cierre.

En la base real, toma el universo auditado de la tabla de revisiones. Si los errores viven en otra tabla, agrega primero el detalle a nivel envío y cruza desde el universo auditado. Trata como 0 los casos que tienen revisión cerrada y confirmada sin error. Conserva los pendientes o resultados desconocidos como tales.

import numpy as np
import pandas as pd
from scipy import stats

USAR_DEMO = True
inicio, fin = "2026-09-01", "2026-10-01"

if USAR_DEMO:
    rng = np.random.default_rng(42)
    grupos = []
    for cedis, n, errores in [("GOMEZ", 1200, 48), ("LEON", 1500, 30)]:
        grupos.append(pd.DataFrame({
            "cedis": cedis,
            "id_envio": [f"{cedis}-{i}" for i in range(n)],
            "fecha": pd.Timestamp(inicio) + pd.to_timedelta(
                rng.integers(0, 30, size=n), unit="D"
            ),
            "error": rng.permutation(np.repeat([1, 0], [errores, n-errores])),
        }))
    raw = pd.concat(grupos, ignore_index=True)
else:
    import os
    from sqlalchemy import create_engine, text
    from sqlalchemy.engine import URL

    motor = create_engine(URL.create(
        "mssql+pyodbc",
        query={"odbc_connect": os.environ["AUDITORIA_ODBC"]}
    ))
    sql = text('''
        SELECT cedis, id_envio, fecha_revision AS fecha,
               error_confirmado AS error
        FROM dbo.vw_envios_auditados
        WHERE fecha_revision >= :inicio AND fecha_revision < :fin
    ''')
    with motor.connect() as conexion:
        raw = pd.read_sql_query(sql, conexion, params={"inicio": inicio, "fin": fin})
    motor.dispose()

Filtra, une y agrega en SQL cuando el origen tenga millones de filas. Trae a pandas las columnas al nivel requerido. Guarda el corte con límite superior exclusivo y concilia contra SQL por CEDIS antes de seguir.

Limpieza y conciliación

Conserva los datos originales y trabaja sobre una copia. Mantén los identificadores como texto para preservar ceros iniciales. Si aparecen duplicados, revisa si vienen de un cruce uno a muchos o de auditorías repetidas y documenta la regla que decide qué registro representa al envío.

df = raw.copy()
for col in ["cedis", "id_envio"]:
    df[col] = df[col].astype("string").str.strip().replace("", pd.NA)
df["cedis"] = df["cedis"].str.upper()
df["fecha"] = pd.to_datetime(df["fecha"], errors="coerce")
df["error"] = pd.to_numeric(df["error"], errors="coerce")

clave = ["cedis", "id_envio"]
duplicado = df.duplicated(clave, keep=False)
fecha_valida = df["fecha"].ge(inicio) & df["fecha"].lt(fin)
incidencia = (
    df[clave].isna().any(axis=1) | duplicado | ~fecha_valida
    | ~df["error"].isin([0, 1])
)
print(pd.Series({
    "filas_sql": len(raw),
    "filas_con_llave_repetida": int(duplicado.sum()),
    "filas_con_incidencia": int(incidencia.sum()),
}))
if incidencia.any():
    print(df.loc[incidencia].head(10))
    raise ValueError("Corrige y concilia las incidencias antes de seguir.")
df["error"] = df["error"].astype("int8")

Análisis exploratorio

Compara el número auditado, los errores y la tasa. Revisa la cobertura de auditoría por semana, turno, tipo de mercancía y criterio de selección cuando tengas esas columnas. Una auditoría dirigida a envíos de alto riesgo cambia a qué población se puede extrapolar el resultado.

orden = ["GOMEZ", "LEON"]
base = df.loc[df["cedis"].isin(orden)].copy()
resumen = (
    base.groupby("cedis")["error"].agg(errores="sum", n="size")
    .reindex(orden)
)
if resumen["n"].isna().any():
    raise ValueError("Se necesitan envíos auditados de ambos CEDIS.")
resumen["tasa"] = resumen["errores"] / resumen["n"]
print(resumen)
print(base.groupby(["cedis", pd.Grouper(key="fecha", freq="W")])["error"]
      .agg(errores="sum", n="size"))

tabla = np.column_stack([
    resumen["errores"].to_numpy(),
    (resumen["n"] - resumen["errores"]).to_numpy(),
])
print(pd.DataFrame(tabla, index=orden, columns=["error", "sin_error"]))

Planteamiento del problema y las hipótesis

Define pG y pL como las probabilidades de error para envíos comparables bajo el esquema de auditoría de cada CEDIS. El resultado es binario y los grupos son distintos. Para el ejercicio asumimos observaciones independientes dentro de cada grupo y entre grupos.

  • H₀ · pG − pL = 0.
  • H₁ · pG − pL ≠ 0. Cualquiera de los CEDIS puede tener mayor tasa.
  • Plan del ejemplo · Prueba bilateral, α = 0.05 e intervalo al 95%. Usamos 1 punto porcentual como umbral operativo ilustrativo, equivalente a 10 errores adicionales por cada 1,000 auditados.

Para diseñar una auditoría nueva, fija el efecto mínimo, la tasa base esperada y la potencia objetivo antes de calcular el tamaño de muestra. Si solo quieres saber si una tasa supera un límite, plantea esa dirección antes de observar los resultados.

Si los envíos comparten caja, lote, turno, ruta o semana, revisa cómo se generó la muestra. La independencia puede fallar aunque cada envío tenga llave única. Según el diseño, analiza al nivel del grupo, usa un modelo con errores agrupados o remuestrea grupos cuando haya suficientes grupos independientes.

PreguntaPrueba y funciónQué revisar
¿La tasa de error supera una meta?Binomial exacta · stats.binomtest. Z de una proporción si la aproximación normal es razonable.Una observación binaria por unidad independiente. Para Z, revisa éxitos y fracasos esperados bajo la meta.

¿El resultado de auditoría se asocia con el turno?Chi cuadrado de independencia · stats.chi2_contingency.Usa frecuencias absolutas y revisa las esperadas. Si hay celdas escasas, considera métodos exactos o simulación válidos para la tabla y el diseño.
¿Cambió la condición conforme/no conforme en las mismas cajas?McNemar · statsmodels.stats.contingency_tables.mcnemar.Pares por caja, independientes entre sí. La prueba se basa en los pares que cambian. Statsmodels se instala aparte.
¿Dos equipos tardan distinto en promedio?t de Welch · stats.ttest_ind(a, b, equal_var=False).Tiempo numérico y grupos independientes. Revisa asimetría y extremos, especialmente con muestras pequeñas. Welch admite varianzas distintas.
¿Cambió el tiempo en las mismas rutas?t pareada · stats.ttest_rel(antes, despues).Alinea por ruta y revisa la distribución de las diferencias, especialmente con pocos pares. Comprueba independencia entre pares.
¿Tres equipos tienen tiempos promedio distintos?ANOVA de un factor o ANOVA de Welch según varianzas.Grupos independientes. La prueba global indica si hay alguna diferencia. Localízala con comparaciones planeadas o ajustadas por multiplicidad.

Si te interesa la mediana, un percentil o la forma de la distribución, define ese objetivo primero. Una prueba de rangos como Mann–Whitney estudia diferencias en el orden de las observaciones. Interpretarla como una diferencia de medianas requiere condiciones adicionales.

Para varios turnos o rubros, considera un contraste global y ajusta las comparaciones posteriores con un método como Holm. Si necesitas ajustar por mezcla de mercancía, turno u otras variables, considera regresión logística para el resultado binario y revisa el diseño de muestreo.

Prueba Z, chi cuadrado e interpretación

La diferencia se calcula como Gómez menos León. Para la prueba Z, estima una proporción combinada bajo H₀ y úsala en el error estándar. Para comunicar el efecto, estima un intervalo de Newcombe basado en los intervalos de Wilson de cada grupo.

alpha = 0.05
x1, x2 = resumen["errores"].to_numpy()
n1, n2 = resumen["n"].to_numpy()
p1, p2 = x1 / n1, x2 / n2
delta = p1 - p2
combinada = (x1 + x2) / (n1 + n2)
esperados = np.outer(tabla.sum(axis=1), tabla.sum(axis=0)) / tabla.sum()
if np.any(esperados < 5):
    raise ValueError("Revisa Fisher exacta para esta tabla 2×2.")

error_estandar_h0 = np.sqrt(combinada * (1 - combinada) * (1/n1 + 1/n2))
z = delta / error_estandar_h0
p_valor = 2 * stats.norm.sf(abs(z))

# Intervalo de Newcombe para la diferencia de proporciones independientes.
ic1 = stats.binomtest(x1, n1).proportion_ci(1 - alpha, method="wilson")
ic2 = stats.binomtest(x2, n2).proportion_ci(1 - alpha, method="wilson")
lim_inf = delta - np.hypot(p1 - ic1.low, ic2.high - p2)
lim_sup = delta + np.hypot(ic1.high - p1, p2 - ic2.low)
print(f"z={z:.3f}, p={p_valor:.4f}")
print(f"Diferencia={100*delta:.2f} pp, IC 95% [{100*lim_inf:.2f}, {100*lim_sup:.2f}]")

Cómo se relacionan Z y chi cuadrado en una tabla 2×2

Para la misma tabla y una prueba Z bilateral, el chi cuadrado de Pearson sin corrección de continuidad equivale a Z² y devuelve el mismo valor p. Son dos formas de contrastar la misma hipótesis con estos datos. Para este ejercicio usamos 5 como regla práctica de frecuencia esperada mínima. Si la tabla es escasa o las categorías carecen de variación, revisa si la prueba elegida resulta aplicable.

# Comparación didáctica sobre los mismos conteos del ejemplo.
chi2 = stats.chi2_contingency(tabla, correction=False)
print(chi2.expected_freq)
assert np.isclose(chi2.statistic, z**2)
assert np.isclose(chi2.pvalue, p_valor)

print(stats.binomtest(x1, n1, p=0.02, alternative="two-sided"))

Redacción para el informe

En el ejemplo, Gómez registró 48 errores en 1,200 envíos auditados (4.00%) y León, 30 en 1,500 (2.00%). La diferencia estimada fue de 2.00 puntos porcentuales. Al nivel del 5%, la prueba detectó una diferencia bajo los supuestos del ejercicio. Como el intervalo incluye diferencias por debajo de 1 punto porcentual, el resultado deja incertidumbre sobre si se supera el umbral operativo propuesto.

El valor p mide qué tan extremo resulta el estadístico, o uno más extremo, si H₀ y los supuestos fueran ciertos. Si p es mayor que α, reporta evidencia insuficiente para detectar la diferencia. La comparación entre CEDIS es observacional. Para atribuir una mejora a un cambio de proceso, diseña una evaluación que permita descartar explicaciones como turno, selección de envíos o mezcla de mercancía.
